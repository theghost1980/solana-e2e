Test connect, sign and send in your Solana dApp — in CI, with no browser extension and no devnet.

A Wallet Standard test wallet your dApp discovers like Phantom. Your test decides what the "user" does: approve, reject, fail, switch account. Optionally, a local Surfpool chain to check what actually landed. 

npm install -D @solana-e2e/wallet @solana-e2e/playwright
import { expect, test } from "@solana-e2e/playwright";

test("a transfer lands", async ({ page, wallet, localnet }) => {
  await page.goto(`/?rpc=${localnet.rpcUrl}`);
  await page.getByRole("button", { name: "Solana E2E Test Wallet" }).click();
  await page.getByRole("button", { name: "Send" }).click();

  const { signature } = await wallet.waitForRequest("signAndSendTransaction");
  const tx = await localnet.getTransaction(signature!);
  expect(tx.err).toBeNull();
});

Why another wallet mock?

How it works

What you can test now

  • The user cancelswallet.rejectNext({ method: "signMessage" })
  • The wallet or the network failswallet.failNext({ code: -32002, message: "Blockhash not found" })
  • A pending approvalwallet.setApproval("manual"); … wallet.approve()
  • The user switches account mid-flowwallet.switchAccount("bob")
  • A wallet without sign-and-send{ disabledFeatures: ["solana:signAndSendTransaction"] }
  • An unsupported transaction version{ supportedTransactionVersions: ["legacy", 0] }
  • autoConnect on an untrusted site{ trusted: false } (the default)
  • An extension that loads lateinstallTestWallet(page, { late: true })

Two modes

mock

Signs for real, sends nothing. For UI tests and for Vitest + jsdom, where registerTestWallet() replaces a hand-written mock-wallet.ts.

const { wallet } = await registerTestWallet({ accounts: ["alice"] });

rpc

Signs, sends to a local RPC and waits for the commitment. With @solana-e2e/playwright you get a Surfpool chain per worker and a funded wallet per test.

const tx = await localnet.getTransaction(signature);
expect(tx.logs).toContain("Program log: hello");

In CI

Mock-mode specs need nothing but Playwright. For rpc mode, install Surfpool from its release and check the archive's sha256; the full GitHub Actions recipe is in docs/ci.md. This project's own CI runs both kinds on Linux, macOS and Windows.

Limitations

  • The Playwright transport is a bridge to Node, so the injected wallet does not work as is in Cypress or Storybook. In-page use (like this playground) works for mock mode.
  • Only Chromium is tested in CI so far.
  • One visible account at a time, as in Phantom.
  • It is a test tool: never give it a key that holds real funds.
